## Chapter 8. Embeddings - 임베딩

### 임베딩이란?

문서 임베딩은 문서의 내용을 수치적인 벡터로 변환하는 과정이다. 이 과정을 통해 문서의 의미를 수치화하고, 다양한 자연어 처리 작업에 활용할 수 있다.

**임베딩의 활용:**

- 문서 분류
- 감성 분석
- 문서 간 유사도 계산
- 검색 (RAG)

---

### OpenAI Embeddings

OpenAI에서 제공하는 임베딩 모델로, 가장 널리 사용되는 방식이다.

**지원 모델:**

| MODEL                  | PAGES PER DOLLAR | PERFORMANCE (MTEB) | MAX INPUT |
| :--------------------- | :--------------: | :----------------: | :-------: |
| text-embedding-3-small |      62,500      |       62.3%        |   8191    |
| text-embedding-3-large |      9,615       |       64.6%        |   8191    |
| text-embedding-ada-002 |      12,500      |       61.0%        |   8191    |

**기본 사용법:**

```python
from langchain_openai import OpenAIEmbeddings

# 임베딩 모델 초기화
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

text = "임베딩 테스트를 하기 위한 샘플 문장입니다."
```

**쿼리 임베딩 (단일 텍스트):**

```python
# 단일 텍스트를 벡터로 변환
query_result = embeddings.embed_query(text)

print(query_result[:5])  # 처음 5개 요소 확인
```

**문서 임베딩 (여러 텍스트):**

```python
# 여러 문서를 한 번에 임베딩
doc_result = embeddings.embed_documents([text1, text2, text3, text4])

print(len(doc_result))  # 문서 개수
print(len(doc_result[0]))  # 각 벡터의 차원 (기본 1536)
```

**차원 조정:**

`text-embedding-3` 모델은 임베딩 차원을 조정할 수 있다.

```python
# 1024 차원으로 줄이기
embeddings_1024 = OpenAIEmbeddings(
    model="text-embedding-3-small",
    dimensions=1024  # 기본값 1536에서 1024로 축소
)

result = embeddings_1024.embed_documents([text])
print(len(result[0]))  # 1024
```

**유사도 계산:**

```python
from sklearn.metrics.pairwise import cosine_similarity

sentence1 = "안녕하세요? 반갑습니다."
sentence2 = "안녕하세요? 반갑습니다!"
sentence3 = "Hi, nice to meet you."
sentence4 = "I like to eat apples."

sentences = [sentence1, sentence2, sentence3, sentence4]
embedded_sentences = embeddings.embed_documents(sentences)

def similarity(a, b):
    return cosine_similarity([a], [b])[0][0]

# 문장 간 유사도 비교
for i, sent_i in enumerate(embedded_sentences):
    for j, sent_j in enumerate(embedded_sentences):
        if i < j:
            print(f"[유사도 {similarity(sent_i, sent_j):.4f}] {sentences[i]} <=> {sentences[j]}")
```

### CacheBackedEmbeddings

임베딩은 비용이 발생하므로, 동일한 텍스트를 반복 임베딩하지 않도록 **캐싱**하는 것이 효율적이다.

**주요 매개변수:**

| 매개변수                   | 설명                           |
| :------------------------- | :----------------------------- |
| `underlying_embeddings`    | 실제 임베딩에 사용할 모델      |
| `document_embedding_cache` | 캐시 저장소 (ByteStore)        |
| `namespace`                | 캐시 충돌 방지용 네임스페이스  |

**LocalFileStore - 영구 저장:**

```python
from langchain.storage import LocalFileStore
from langchain_openai import OpenAIEmbeddings
from langchain.embeddings import CacheBackedEmbeddings
from langchain_community.vectorstores.faiss import FAISS

# 기본 임베딩 모델
embedding = OpenAIEmbeddings()

# 로컬 파일 저장소 (./cache/ 폴더에 저장)
store = LocalFileStore("./cache/")

# 캐시 지원 임베딩 생성
cached_embedder = CacheBackedEmbeddings.from_bytes_store(
    underlying_embeddings=embedding,
    document_embedding_cache=store,
    namespace=embedding.model,  # 모델명으로 네임스페이스 설정
)
```

**캐시 효과 확인:**

```python
from langchain.document_loaders import TextLoader
from langchain_text_splitters import CharacterTextSplitter

# 문서 로드 및 분할
raw_documents = TextLoader("./data/appendix-keywords.txt").load()
text_splitter = CharacterTextSplitter(chunk_size=1000, chunk_overlap=0)
documents = text_splitter.split_documents(raw_documents)

# 첫 번째 실행 - 임베딩 계산
%time db = FAISS.from_documents(documents, cached_embedder)
# Wall time: 2.5s

# 두 번째 실행 - 캐시에서 로드 (훨씬 빠름!)
%time db2 = FAISS.from_documents(documents, cached_embedder)
# Wall time: 0.1s
```

**InMemoryByteStore - 임시 저장:**

```python
from langchain.storage import InMemoryByteStore

# 메모리 내 저장소 (프로그램 종료 시 삭제됨)
store = InMemoryByteStore()

cached_embedder = CacheBackedEmbeddings.from_bytes_store(
    embedding, store, namespace=embedding.model
)
```

### HuggingFace Embeddings

오픈소스 임베딩 모델을 사용할 수 있다. 무료이며 로컬에서 실행 가능하다.

```python
# 문서 임베딩
embedded_documents = hf_embeddings.embed_documents(texts)

```

**HuggingFace Embeddings (로컬 실행):**

```python
from langchain_huggingface.embeddings import HuggingFaceEmbeddings

model_name = "intfloat/multilingual-e5-large-instruct"

hf_embeddings = HuggingFaceEmbeddings(
    model_name=model_name,
    model_kwargs={"device": "cuda"},  # cuda, cpu, mps(Mac)
    encode_kwargs={"normalize_embeddings": True},
)

embedded_documents = hf_embeddings.embed_documents(texts)
```

**BGE-M3 모델:**

BAAI에서 개발한 다국어 임베딩 모델로, 한국어 성능이 우수하다.

```python

hf_embeddings = HuggingFaceEmbeddings(
    model_name=model_name,
    model_kwargs={"device": "cuda"},
    encode_kwargs={"normalize_embeddings": True},

embedded_documents = hf_embeddings.embed_documents(texts)
print(f"Dimension: {len(embedded_documents[0])}")  # 1024
```

**유사도 계산 (벡터 내적):**

```python
import numpy as np

embedded_query = hf_embeddings.embed_query("LangChain 에 대해서 알려주세요.")
embedded_documents = hf_embeddings.embed_documents(texts)

# 벡터 내적으로 유사도 계산
similarities = np.array(embedded_query) @ np.array(embedded_documents).T

# 유사도 기준 정렬
sorted_idx = similarities.argsort()[::-1]

for i, idx in enumerate(sorted_idx):
    print(f"[{i}] {texts[idx]}")
```

### BGE-M3의 세 가지 임베딩 방식

FlagEmbedding 라이브러리를 사용하면 BGE-M3의 다양한 임베딩 방식을 활용할 수 있다.

**1. Dense Embedding (기본):**

```python
from FlagEmbedding import BGEM3FlagModel

bge_embeddings = BGEM3FlagModel("BAAI/bge-m3", use_fp16=True)

bge_encoded = bge_embeddings.encode(
    texts,
    batch_size=12,
    max_length=8192,
)["dense_vecs"]

print(bge_encoded.shape)  # (5, 1024)
```

**2. Sparse Embedding (Lexical Weight):**

단어의 중요도(TF-IDF, BM25 유사)를 기반으로 sparse vector 생성.

```python
bge_encoded = bge_embeddings.encode(texts, return_sparse=True)

# Lexical 매칭 점수 계산
score = bge_embeddings.compute_lexical_matching_score(
    bge_encoded["lexical_weights"][0],
    bge_encoded["lexical_weights"][1]
)
```

**장점:**
- 특정 단어/구문 정확 매칭
- 계산이 빠름

**3. Multi-Vector (ColBERT):**

문서의 각 토큰에 대해 별도 벡터 생성. 세밀한 매칭 가능.

```python
bge_encoded = bge_embeddings.encode(texts, return_colbert_vecs=True)

# ColBERT 점수 계산
score = bge_embeddings.colbert_score(
    bge_encoded["colbert_vecs"][0],
    bge_encoded["colbert_vecs"][1]
)
```

**장점:**
- 토큰 수준의 세밀한 매칭
- 문맥을 고려한 임베딩
- 긴 문서에 효과적

### Upstage Embeddings

국내 스타트업 Upstage에서 제공하는 Solar 기반 임베딩.

**모델 종류:**

| Model                           | Context | 설명                    |
| :------------------------------ | :-----: | :---------------------- |
| solar-embedding-1-large-query   |  4000   | 사용자 질문 임베딩 최적화    |
| solar-embedding-1-large-passage |  4000   | 문서/텍스트 임베딩 최적화   |

```python
# 문서용 임베딩 모델

# 쿼리 임베딩

# 문서 임베딩

```

**유사도 계산:**

```python
import numpy as np

similarity = np.array(embedded_query) @ np.array(embedded_documents).T
sorted_idx = similarity.argsort()[::-1]

for i, idx in enumerate(sorted_idx):
    print(f"[{i}] 유사도: {similarity[idx]:.3f} | {texts[idx]}")
```

## 헷갈렸던 부분

### embed_query() vs embed_documents()

처음에 이 두 메서드의 차이가 헷갈렸다.

| 메서드              | 입력          | 출력               | 용도                |
| :------------------ | :------------ | :----------------- | :------------------ |
| `embed_query()`     | `str`         | `List[float]`      | 단일 검색 쿼리      |
| `embed_documents()` | `List[str]`   | `List[List[float]]`| 여러 문서 일괄 처리 |

```python
# embed_query - 단일 텍스트, 단일 벡터 반환
query_vec = embeddings.embed_query("검색어")
# [0.1, -0.2, 0.3, ...]

# embed_documents - 여러 텍스트, 여러 벡터 반환
doc_vecs = embeddings.embed_documents(["문서1", "문서2", "문서3"])
# [[0.1, -0.2, ...], [0.3, -0.1, ...], [0.2, 0.4, ...]]
```

**결론:** 검색 시스템에서는 쿼리는 `embed_query()`, 문서들은 `embed_documents()`를 사용한다.

### 벡터 내적과 코사인 유사도

유사도 계산에서 벡터 내적을 사용하는 이유가 궁금했다.

**벡터 내적 공식:**

$$\mathbf{a} \cdot \mathbf{b} = \|\mathbf{a}\| \|\mathbf{b}\| \cos \theta$$

- $\|\mathbf{a}\|$, $\|\mathbf{b}\|$: 벡터의 크기 (노름)
- $\theta$: 두 벡터 사이의 각도
- $\cos \theta$: 코사인 유사도

**정규화된 벡터의 경우:**

임베딩이 정규화되어 있으면 ($\|\mathbf{a}\| = \|\mathbf{b}\| = 1$):

$$\mathbf{a} \cdot \mathbf{b} = \cos \theta$$

→ **벡터 내적 = 코사인 유사도**

```python
# 정규화된 임베딩 사용
hf_embeddings = HuggingFaceEmbeddings(
    model_name=model_name,
    encode_kwargs={"normalize_embeddings": True},  # 정규화!
)

# 이제 단순 내적으로 유사도 계산 가능
similarity = np.array(query) @ np.array(documents).T
```

## 궁금해서 더 찾아본 내용

### 1. 왜 Query와 Document 임베딩 모델이 따로 있나? (Upstage)

> "embed_query와 embed_documents가 있는데, 왜 Upstage는 모델 자체를 분리했나?"

Upstage의 Solar 임베딩은 **비대칭 검색(Asymmetric Search)**에 최적화되어 있다.

- **Query 모델**: 짧은 질문에 최적화
- **Passage 모델**: 긴 문서에 최적화

이렇게 하면 질문과 문서의 특성에 맞는 임베딩을 생성하여 검색 정확도가 높아진다.

---

### 2. 차원을 줄이면 성능이 떨어지지 않나?

> "text-embedding-3-small의 차원을 1536에서 1024로 줄이면?"

OpenAI의 `text-embedding-3` 모델은 **Matryoshka Representation Learning**을 사용한다.

- 임베딩의 앞부분에 더 중요한 정보가 집중됨
- 차원을 줄여도 성능 저하가 상대적으로 적음
- 저장 공간 및 계산 비용 절감 가능

```python
# 차원별 권장 사용 사례
# 1536: 최고 정확도 필요
# 1024: 균형 (성능 vs 비용)
# 512: 대규모 데이터, 비용 민감
# 256: 빠른 프로토타이핑
```

---

### 3. CacheBackedEmbeddings의 namespace는 왜 필요한가?

> "namespace를 설정 안 하면 어떻게 되나?"

동일한 텍스트라도 다른 모델로 임베딩하면 결과가 다르다.

```python
# 모델 A로 "안녕하세요" 임베딩 → [0.1, 0.2, ...]
# 모델 B로 "안녕하세요" 임베딩 → [0.5, -0.3, ...]
```

namespace가 없으면 텍스트 해시만으로 캐시 키를 만들어서, 다른 모델의 임베딩이 섞일 수 있다.

**권장:** `namespace=embedding.model`로 모델명을 namespace로 사용

## 이번 주 핵심 정리

1. **임베딩 = 텍스트 → 벡터 변환** → 의미를 수치화하여 유사도 계산 가능
2. **OpenAI 임베딩이 가장 쉬움** → `text-embedding-3-small` 추천, 차원 조정 가능
3. **CacheBackedEmbeddings로 비용 절감** → 동일 텍스트 재임베딩 방지
4. **오픈소스는 BGE-M3 추천** → 한국어 성능 우수, Dense/Sparse/ColBERT 지원
5. **로컬 실행은 Ollama가 편함** → `ollama pull nomic-embed-text`
6. **유사도 계산은 벡터 내적** → 정규화된 임베딩이면 코사인 유사도와 동일
7. **Query/Document 구분 필요** → 비대칭 검색에서 중요
