## Chapter 13. Retriever - 리트리버

### 리트리버란?

리트리버(Retriever)는 벡터스토어에 저장된 문서 중에서 사용자의 쿼리와 관련된 문서를 검색하여 반환하는 컴포넌트다. RAG 파이프라인에서 검색 품질을 결정짓는 핵심 역할을 한다.

**리트리버의 역할:**

1. 사용자 쿼리를 받아 관련 문서 검색
2. 검색 결과의 품질 및 다양성 향상
3. LCEL 체인에 연결하여 RAG 파이프라인 구성

### VectorStore Retriever (벡터스토어 기반 검색기)

VectorStore에 구현된 유사도 검색(similarity search)이나 MMR과 같은 검색 메서드를 사용하여 벡터 스토어 내의 텍스트를 쿼리한다.

**기본 사용법:**

```python
from langchain_community.vectorstores import FAISS
from langchain_openai import OpenAIEmbeddings
from langchain_text_splitters import CharacterTextSplitter
from langchain_community.document_loaders import TextLoader

loader = TextLoader("./data/appendix-keywords.txt")
documents = loader.load()

text_splitter = CharacterTextSplitter(chunk_size=300, chunk_overlap=0)
split_docs = text_splitter.split_documents(documents)

embeddings = OpenAIEmbeddings()
db = FAISS.from_documents(split_docs, embeddings)

# Retriever 생성
retriever = db.as_retriever()
docs = retriever.invoke("임베딩(Embedding)은 무엇인가요?")
```

**검색 유형:**

| search_type | 설명 | 주요 파라미터 |
| :--- | :--- | :--- |
| `similarity` | 유사도 기반 검색 (기본값) | `k` |
| `mmr` | Maximal Marginal Relevance - 다양성 고려 | `k`, `fetch_k`, `lambda_mult` |
| `similarity_score_threshold` | 임계값 이상의 유사도만 반환 | `score_threshold` |

**MMR 검색:**

```python
retriever = db.as_retriever(
    search_type="mmr",
    search_kwargs={"k": 2, "fetch_k": 10, "lambda_mult": 0.6}
)
docs = retriever.invoke("임베딩(Embedding)은 무엇인가요?")
```

**유사도 점수 임계값 검색:**

```python
retriever = db.as_retriever(
    search_type="similarity_score_threshold",
    search_kwargs={"score_threshold": 0.8},
)
docs = retriever.invoke("Word2Vec 은 무엇인가요?")
```

**동적 설정 (ConfigurableField):**

런타임에 검색 설정을 동적으로 변경할 수 있다.

```python
from langchain_core.runnables import ConfigurableField

retriever = db.as_retriever(search_kwargs={"k": 1}).configurable_fields(
    search_type=ConfigurableField(id="search_type", name="Search Type"),
    search_kwargs=ConfigurableField(id="search_kwargs", name="Search Kwargs"),
)

# 런타임에 설정 변경
config = {"configurable": {"search_kwargs": {"k": 3}}}
docs = retriever.invoke("임베딩(Embedding)은 무엇인가요?", config=config)
```

### ContextualCompressionRetriever (문맥 압축 검색기)

검색된 문서를 그대로 반환하는 대신, 주어진 질의의 맥락을 사용하여 문서를 **압축**함으로써 관련 정보만 반환한다. "압축"은 개별 문서의 내용을 줄이는 것과 문서를 필터링하는 것 모두를 의미한다.

**LLMChainExtractor - LLM으로 관련 내용 추출:**

```python
from langchain_teddynote.document_compressors import LLMChainExtractor
from langchain.retrievers import ContextualCompressionRetriever
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(temperature=0, model="gpt-4o-mini")

# LLM을 사용하여 문서 압축기 생성
compressor = LLMChainExtractor.from_llm(llm)
compression_retriever = ContextualCompressionRetriever(
    base_compressor=compressor,
    base_retriever=retriever,
)

compressed_docs = compression_retriever.invoke("Semantic Search 에 대해서 알려줘.")
```

**LLMChainFilter - LLM으로 문서 필터링:**

문서 내용을 변경하지 않고, 관련 문서만 **선택적으로 반환**한다.

```python
from langchain_teddynote.document_compressors import LLMChainFilter

_filter = LLMChainFilter.from_llm(llm)
compression_retriever = ContextualCompressionRetriever(
    base_compressor=_filter,
    base_retriever=retriever,
)
```

**EmbeddingsFilter - 임베딩 유사도로 필터링:**

LLM 호출 없이 임베딩 유사도만으로 필터링하여 비용과 속도를 절약한다.

```python
from langchain.retrievers.document_compressors import EmbeddingsFilter
from langchain_openai import OpenAIEmbeddings

embeddings_filter = EmbeddingsFilter(
    embeddings=OpenAIEmbeddings(), similarity_threshold=0.86
)
compression_retriever = ContextualCompressionRetriever(
    base_compressor=embeddings_filter, base_retriever=retriever
)
```

**DocumentCompressorPipeline - 파이프라인 구성:**

여러 compressor를 순차적으로 결합할 수 있다.

```python
from langchain.retrievers.document_compressors import DocumentCompressorPipeline
from langchain_community.document_transformers import EmbeddingsRedundantFilter

pipeline_compressor = DocumentCompressorPipeline(
    transformers=[
        splitter,           # 1. 문서 분할
        redundant_filter,   # 2. 중복 제거 (유사도 0.95 이상을 중복으로 간주)
        relevant_filter,    # 3. 관련성 필터링
        LLMChainExtractor.from_llm(llm),  # 4. LLM으로 내용 추출
    ]
)
```

### EnsembleRetriever (앙상블 검색기)

여러 검색기를 결합하여 더 강력한 검색 결과를 제공한다. **Reciprocal Rank Fusion** 알고리즘을 사용하여 결과의 순위를 조정한다.

**주요 특징:**

- **Sparse Retriever (BM25)**: 키워드 기반 검색에 효과적
- **Dense Retriever (임베딩 유사도)**: 의미적 유사성 기반 검색에 효과적

```python
from langchain.retrievers import BM25Retriever, EnsembleRetriever
from langchain.vectorstores import FAISS
from langchain_openai import OpenAIEmbeddings

doc_list = ["I like apples", "I like apple company", "I like apple's iphone"]

# BM25 Retriever
bm25_retriever = BM25Retriever.from_texts(doc_list)
bm25_retriever.k = 1

# FAISS Retriever
faiss_vectorstore = FAISS.from_texts(doc_list, OpenAIEmbeddings())
faiss_retriever = faiss_vectorstore.as_retriever(search_kwargs={"k": 1})

# 앙상블 Retriever (BM25 70%, FAISS 30%)
ensemble_retriever = EnsembleRetriever(
    retrievers=[bm25_retriever, faiss_retriever],
    weights=[0.7, 0.3],
)

result = ensemble_retriever.invoke("my favorite fruit is apple")
```

**런타임 가중치 변경:**

```python
from langchain_core.runnables import ConfigurableField

ensemble_retriever = EnsembleRetriever(
    retrievers=[bm25_retriever, faiss_retriever],
).configurable_fields(
    weights=ConfigurableField(id="ensemble_weights")
)

# BM25에만 가중치 부여
config = {"configurable": {"ensemble_weights": [1, 0]}}
docs = ensemble_retriever.invoke("my favorite fruit is apple", config=config)
```

### LongContextReorder (긴 문맥 재정렬)

10개 이상의 검색 문서를 포함할 경우 성능이 저하되는 문제를 해결한다. 모델이 긴 컨텍스트 **중간에 있는 관련 정보를 무시하는 경향**이 있기 때문에, 관련 문서를 **시작과 끝에 배치**하는 방식으로 재정렬한다.

```python
from langchain_community.document_transformers import LongContextReorder

# 검색 수행
docs = retriever.invoke("ChatGPT에 대해 무엇을 말해줄 수 있나요?")

# 문서 재정렬 (관련 문서가 시작과 끝에 위치)
reordering = LongContextReorder()
reordered_docs = reordering.transform_documents(docs)
```

**체인에 적용:**

```python
from langchain_core.runnables import RunnableLambda

chain = (
    {
        "context": itemgetter("question")
        | retriever
        | RunnableLambda(reorder_documents),  # 재정렬 적용
        "question": itemgetter("question"),
        "language": itemgetter("language"),
    }
    | prompt
    | ChatOpenAI(model="gpt-4o-mini")
    | StrOutputParser()
)
```

### ParentDocumentRetriever (부모 문서 검색기)

문서 검색에서 **작은 청크로 정확한 임베딩**을 만들면서도 **충분한 맥락을 유지**하는 두 가지 상충되는 요구사항을 해결한다. 작은 청크로 검색하되, 해당 청크가 속한 원본(부모) 문서를 반환한다.

**전체 문서 검색:**

```python
from langchain.retrievers import ParentDocumentRetriever
from langchain.storage import InMemoryStore
from langchain_text_splitters import RecursiveCharacterTextSplitter

child_splitter = RecursiveCharacterTextSplitter(chunk_size=200)

vectorstore = Chroma(collection_name="full_documents", embedding_function=OpenAIEmbeddings())
store = InMemoryStore()

retriever = ParentDocumentRetriever(
    vectorstore=vectorstore,
    docstore=store,
    child_splitter=child_splitter,
)

retriever.add_documents(docs, ids=None)
```

**더 큰 청크 검색 (Parent + Child 분리):**

```python
# 부모: 1000자, 자식: 200자
parent_splitter = RecursiveCharacterTextSplitter(chunk_size=1000)
child_splitter = RecursiveCharacterTextSplitter(chunk_size=200)

retriever = ParentDocumentRetriever(
    vectorstore=vectorstore,
    docstore=store,
    child_splitter=child_splitter,
    parent_splitter=parent_splitter,  # 부모 분할기 추가
)
```

> 자식 청크로 검색 → 부모 청크를 반환 (전체 문서가 아닌 적절한 크기)

### MultiQueryRetriever (다중 쿼리 검색기)

사용자의 쿼리를 LLM을 활용하여 **다양한 관점의 여러 쿼리로 자동 변환**한 후, 각 쿼리의 검색 결과를 합집합으로 반환한다. 거리 기반 검색의 한계를 극복한다.

```python
from langchain.retrievers.multi_query import MultiQueryRetriever
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(temperature=0, model="gpt-4o-mini")

multiquery_retriever = MultiQueryRetriever.from_llm(
    retriever=db.as_retriever(),
    llm=llm,
)

# 내부적으로 여러 쿼리를 생성하여 검색
relevant_docs = multiquery_retriever.invoke(
    "OpenAI Assistant API의 Functions 사용법에 대해 알려주세요."
)
```

**커스텀 프롬프트로 쿼리 생성:**

```python
from langchain_core.prompts import PromptTemplate

prompt = PromptTemplate.from_template(
    """You are an AI language model assistant.
Your task is to generate five different versions of the given user question.
#ORIGINAL QUESTION: {question}
#Answer in Korean:"""
)

custom_chain = {"question": RunnablePassthrough()} | prompt | llm | StrOutputParser()

multiquery_retriever = MultiQueryRetriever.from_llm(
    llm=custom_chain, retriever=db.as_retriever()
)
```

### MultiVectorRetriever (다중 벡터 검색기)

문서를 **여러 벡터로 저장하고 관리**하여 검색 정확도를 향상시킨다.

**문서당 여러 벡터 생성 방법:**

| 방법 | 설명 |
| :--- | :--- |
| 작은 청크 생성 | 문서를 더 작은 단위로 나눠 각각 임베딩 |
| 요약 임베딩 | 문서 요약으로부터 임베딩 생성 |
| 가설 질문 활용 | 문서에 대한 가설 질문을 생성하여 임베딩 |

**요약본을 벡터저장소에 저장:**

```python
from langchain.retrievers.multi_vector import MultiVectorRetriever

# 요약 체인 생성
summary_chain = (
    {"doc": lambda x: x.page_content}
    | ChatPromptTemplate.from_messages([
        ("system", "You are an expert in summarizing documents in Korean."),
        ("user", "Summarize the following documents in 3 sentences.\n\n{doc}"),
    ])
    | ChatOpenAI(temperature=0, model="gpt-4o-mini")
    | StrOutputParser()
)

# 요약 생성
summaries = summary_chain.batch(split_docs, {"max_concurrency": 10})

# 벡터저장소에 요약 저장, docstore에 원본 저장
retriever.vectorstore.add_documents(summary_docs)
retriever.docstore.mset(list(zip(doc_ids, split_docs)))
```

**가설 쿼리(Hypothetical Queries) 활용:**

```python
# Function Calling을 활용하여 가설 질문 생성
hypothetical_query_chain = (
    {"doc": lambda x: x.page_content}
    | ChatPromptTemplate.from_template(
        "Generate a list of exactly 3 hypothetical questions "
        "that the below document could be used to answer.\n\n{doc}"
    )
    | ChatOpenAI(model="gpt-4o-mini").bind(
        functions=functions,
        function_call={"name": "hypothetical_questions"}
    )
    | JsonKeyOutputFunctionsParser(key_name="questions")
)

hypothetical_questions = hypothetical_query_chain.batch(split_docs, {"max_concurrency": 10})
```

### SelfQueryRetriever (셀프 쿼리 검색기)

사용자의 자연어 질의에서 **메타데이터 필터를 자동으로 추출**하여 구조화된 검색을 수행한다. 의미적 비교를 넘어 메타데이터 기반 필터링이 가능하다.

```python
from langchain.chains.query_constructor.base import AttributeInfo
from langchain.retrievers.self_query.base import SelfQueryRetriever

# 메타데이터 필드 정보 정의
metadata_field_info = [
    AttributeInfo(name="category", description="The category", type="string"),
    AttributeInfo(name="year", description="The year released", type="integer"),
    AttributeInfo(name="user_rating", description="User rating 1-5", type="float"),
]

retriever = SelfQueryRetriever.from_llm(
    llm=ChatOpenAI(model="gpt-4o-mini", temperature=0),
    vectorstore=vectorstore,
    document_contents="Brief summary of a cosmetic product",
    metadata_field_info=metadata_field_info,
)

# 메타데이터 필터가 자동 적용됨
retriever.invoke("평점이 4.8 이상인 제품을 추천해주세요")
retriever.invoke("2023년에 출시된 상품을 추천해주세요")
```

**검색 결과 수 제한:**

```python
retriever = SelfQueryRetriever.from_llm(
    llm=llm,
    vectorstore=vectorstore,
    document_contents="Brief summary of a cosmetic product",
    metadata_field_info=metadata_field_info,
    enable_limit=True,  # 검색 결과 제한 기능 활성화
)

# 자연어로 결과 수 제한
retriever.invoke("2023년에 출시된 상품 1개를 추천해주세요")
```

### TimeWeightedVectorStoreRetriever (시간 가중 검색기)

의미론적 유사성과 **시간에 따른 감쇠**를 결합하여 정보의 "신선함"과 "관련성"을 모두 고려한다.

**스코어링 공식:**

$$\text{semantic\_similarity} + (1.0 - \text{decay\_rate})^{hours\_passed}$$

```python
from langchain.retrievers import TimeWeightedVectorStoreRetriever

# 낮은 감쇠율 (정보를 거의 잊지 않음 → 유사도 중심)
retriever = TimeWeightedVectorStoreRetriever(
    vectorstore=vectorstore, decay_rate=0.0000000000000000000000001, k=1
)

# 높은 감쇠율 (과거 정보를 빠르게 잊음 → 최신 정보 중심)
retriever = TimeWeightedVectorStoreRetriever(
    vectorstore=vectorstore, decay_rate=0.999, k=1
)
```

**decay_rate 정리:**

| decay_rate | 특성 | 결과 |
| :---: | :--- | :--- |
| 0에 가까움 | 정보를 거의 잊지 않음 | 유사도에 높은 점수 부여 |
| 1에 가까움 | 과거 정보를 빠르게 잊음 | 최신 정보에 높은 점수 부여 |
| 1.0 | 모든 recency가 0 | Vector Lookup과 동일 |

### BM25Retriever + 한국어 형태소 분석기

한국어 검색에서 BM25는 공백 기반 토큰화의 한계가 있다. **형태소 분석기(Kiwi)**를 전처리 함수로 적용하면 검색 품질이 크게 향상된다.

**문제점:**

기본 BM25는 공백으로만 토큰을 분리하므로, "금융보험"과 "금융 보험"을 다르게 인식한다.

```python
from kiwipiepy import Kiwi

kiwi = Kiwi()

# 토큰화 함수
def kiwi_tokenize(text):
    return [token.form for token in kiwi.tokenize(text)]

# Kiwi 형태소 분석기 적용 BM25
kiwi_bm25 = BM25Retriever.from_documents(docs, preprocess_func=kiwi_tokenize)
```

**다양한 형태소 분석기 비교:**

| 분석기 | 라이브러리 | 특징 |
| :--- | :--- | :--- |
| Kiwi | `kiwipiepy` | 빠르고 정확, 사용자 사전 추가 가능 |
| Kkma | `konlpy` | 정밀한 분석, 속도 느림 |
| Okt | `konlpy` | 속도 빠름, SNS 텍스트에 강함 |
| Komoran | `konlpy` | 가볍고 빠름 |
| Hannanum | `konlpy` | KAIST 개발, 기본적인 분석 |

**앙상블 + Kiwi BM25 조합:**

```python
kiwibm25_faiss_73 = EnsembleRetriever(
    retrievers=[kiwi_bm25, faiss],
    weights=[0.7, 0.3],
    search_type="mmr",
)
```

> 실험 결과, `kiwi_bm25 + FAISS` 앙상블 조합이 한국어 검색에서 가장 안정적인 결과를 보여줬다. 기본 BM25는 "금융보험"(붙여쓰기)에서 "금융보씨 험한말..." 같은 엉뚱한 결과를 반환하지만, Kiwi BM25는 올바르게 검색한다.

## 헷갈렸던 부분

### ContextualCompression의 세 가지 방식

처음에 LLMChainExtractor, LLMChainFilter, EmbeddingsFilter의 차이가 명확하지 않았다.

| 방식 | 동작 | 비용 | 속도 |
| :--- | :--- | :--- | :--- |
| `LLMChainExtractor` | 문서에서 관련 내용만 **추출** (내용 변경) | 높음 | 느림 |
| `LLMChainFilter` | 관련 문서만 **선택** (내용 변경 없음) | 높음 | 느림 |
| `EmbeddingsFilter` | 임베딩 유사도로 문서 **필터링** | 낮음 | 빠름 |

**결론:** 비용이 민감하면 `EmbeddingsFilter`, 정확도가 중요하면 `LLMChainExtractor`를 사용하면 된다.

### ParentDocumentRetriever의 parent_splitter 유무 차이

`parent_splitter`를 지정하지 않으면 **전체 원본 문서**가 반환되고, 지정하면 **더 큰 청크 단위**로 반환된다.

```python
# parent_splitter 없음 → 전체 문서 반환 (문서 길이가 매우 클 수 있음)
retriever = ParentDocumentRetriever(
    vectorstore=vectorstore, docstore=store, child_splitter=child_splitter,
)

# parent_splitter 있음 → 1000자 청크 반환 (적절한 크기)
retriever = ParentDocumentRetriever(
    vectorstore=vectorstore, docstore=store,
    child_splitter=child_splitter,
    parent_splitter=parent_splitter,  # 1000자 단위
)
```

**결론:** 전체 문서가 짧으면 `parent_splitter` 없이, 전체 문서가 길면 `parent_splitter`를 지정하여 적절한 크기의 맥락을 반환하는 것이 좋다.

---

### MultiVectorRetriever에서 vectorstore.similarity_search vs retriever.invoke 차이

| 메서드 | 반환 대상 | 용도 |
| :--- | :--- | :--- |
| `retriever.vectorstore.similarity_search()` | 벡터저장소의 청크/요약/가설쿼리 | 중간 결과 확인 |
| `retriever.invoke()` | docstore에 저장된 **원본 문서** | 최종 검색 결과 |

```python
# 벡터저장소에서 검색 → 요약본이 반환됨
result = summary_vectorstore.similarity_search("질문")

# retriever로 검색 → 원본 문서가 반환됨
result = retriever.invoke("질문")
```

**결론:** `MultiVectorRetriever`는 벡터저장소에서 유사도가 높은 항목을 찾고, 그 항목의 `doc_id`를 통해 docstore에서 원본 문서를 가져오는 2단계 검색을 수행한다.

## 궁금해서 더 찾아본 내용

### 1. Reciprocal Rank Fusion(RRF)은 어떻게 동작하나?

> "EnsembleRetriever의 weights가 어떻게 결과에 영향을 미치는 건가?"

RRF는 여러 검색기의 결과를 통합하는 알고리즘이다.

$$RRF(d) = \sum_{r \in R} \frac{1}{k + r(d)}$$

- $R$: 검색기 목록
- $r(d)$: 검색기 $r$에서 문서 $d$의 순위
- $k$: 상수 (보통 60)

각 검색기에서 문서가 상위에 있을수록 높은 점수를 받고, weights는 각 검색기의 RRF 점수에 곱해지는 가중치 역할을 한다.

**결론:** `weights=[0.7, 0.3]`이면 BM25의 RRF 점수에 0.7을, FAISS의 RRF 점수에 0.3을 곱한 후 합산하여 최종 순위를 결정한다.

### 2. SelfQueryRetriever는 내부적으로 어떻게 필터를 생성하나?

> "자연어를 어떻게 구조화된 필터로 변환하는 건가?"

내부적으로 `query-constructor` LLM 체인이 동작한다.

```python
from langchain.chains.query_constructor.base import get_query_constructor_prompt

prompt = get_query_constructor_prompt(
    "Brief summary of a cosmetic product",
    metadata_field_info,
)
```

이 프롬프트에는 메타데이터 필드 정보와 허용되는 비교 연산자(`eq`, `gt`, `lt` 등)가 포함되어 있다. LLM이 사용자 쿼리를 분석하여 `StructuredQuery` 객체를 생성하고, 이를 벡터스토어에 맞는 필터로 변환한다.

**변환 과정:**
1. 사용자 쿼리 → LLM → `StructuredQuery` (쿼리 + 필터)
2. `StructuredQuery` → `ChromaTranslator` → Chroma 필터 문법

### 3. 한국어 BM25에서 형태소 분석기가 왜 중요한가?

> "기본 BM25가 왜 '금융보험'을 제대로 검색하지 못하나?"

기본 BM25는 공백으로 토큰을 분리한다. 한국어는 교착어이므로:

- "금융보험" → 토큰 1개: `["금융보험"]`
- "금융보씨 험한말 좀 하지마시고" → 토큰에 "금융보" 포함 → 부분 매칭

Kiwi 형태소 분석기를 적용하면:

- "금융보험" → `["금융", "보험"]`
- "금융보씨 험한말..." → `["금융", "보", "씨", "험하", ...]`

형태소 단위로 분리되면 "금융"과 "보험" 두 토큰이 모두 포함된 문서를 정확히 찾을 수 있다.

**결론:** 한국어 BM25 검색에서는 Kiwi 형태소 분석기를 `preprocess_func`으로 반드시 적용하는 것이 좋다.

## 이번 주 핵심 정리

1. **VectorStore Retriever가 기본** → `as_retriever()`로 변환, similarity/MMR/threshold 검색 지원
2. **ContextualCompression으로 검색 품질 향상** → LLM으로 문서 압축/필터링, 파이프라인 구성 가능
3. **EnsembleRetriever로 하이브리드 검색** → BM25(키워드) + Dense(의미) 결합, RRF로 순위 통합
4. **LongContextReorder로 Lost in the Middle 방지** → 관련 문서를 시작/끝에 배치
5. **ParentDocumentRetriever로 정확도 + 맥락 확보** → 작은 청크로 검색, 큰 청크/원본 반환
6. **MultiQueryRetriever로 검색 범위 확장** → LLM이 다양한 관점의 쿼리 자동 생성
7. **MultiVectorRetriever로 다양한 표현 활용** → 요약/가설 질문으로 검색, 원본 문서 반환
8. **SelfQueryRetriever로 메타데이터 자동 필터링** → 자연어에서 필터 조건 자동 추출
9. **TimeWeightedRetriever로 시간 가중치 적용** → decay_rate로 신선함 vs 관련성 조절
10. **한국어 BM25는 Kiwi 형태소 분석기 필수** → 공백 기반 토큰화의 한계 극복, 앙상블과 결합 시 최적
