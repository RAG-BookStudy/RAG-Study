## Chapter 9. Document Loader - 문서 로더

### Document 객체란?

LangChain에서 모든 문서는 `Document` 객체로 표현된다. 이 객체는 두 가지 속성을 가진다.

```python
from langchain_core.documents import Document

document = Document(page_content="안녕하세요? 이건 랭체인의 도큐먼트입니다")

# 도큐먼트의 속성 확인
document.__dict__
# {'page_content': '안녕하세요? 이건 랭체인의 도큐먼트입니다', 'metadata': {}}
```

**Document 객체의 속성:**

| 속성           | 설명                         | 예시                              |
| :------------- | :--------------------------- | :-------------------------------- |
| `page_content` | 문서의 실제 내용 (문자열)    | "안녕하세요..."                   |
| `metadata`     | 문서의 메타데이터 (딕셔너리) | {"source": "file.pdf", "page": 1} |

**메타데이터 추가하기:**

```python
# 메타데이터 추가
document.metadata["source"] = "TeddyNote"
document.metadata["page"] = 1
document.metadata["author"] = "Teddy"

print(document.metadata)
# {'source': 'TeddyNote', 'page': 1, 'author': 'Teddy'}
```

### Document Loader의 주요 메서드

모든 Document Loader는 공통적인 메서드를 제공한다.

| 메서드                     | 반환 타입        | 설명                                   |
| :------------------------- | :--------------- | :------------------------------------- |
| `load()`                   | `List[Document]` | 문서를 로드하여 리스트로 반환          |
| `load_and_split(splitter)` | `List[Document]` | 로드 후 분할까지 한 번에               |
| `lazy_load()`              | `Generator`      | 제너레이터 방식으로 메모리 효율적 로드 |
| `aload()`                  | `Coroutine`      | 비동기 방식으로 로드                   |

**load() 기본 사용:**

```python
from langchain_community.document_loaders import PyPDFLoader

loader = PyPDFLoader("./data/SPRI_AI_Brief_2023년12월호_F.pdf")
docs = loader.load()

print(f"문서의 수: {len(docs)}")  # 페이지 수만큼 Document 생성
print(docs[0].page_content[:200])  # 첫 페이지 내용
print(docs[0].metadata)  # {'source': '...', 'page': 0}
```

**load_and_split() - 로드와 분할을 한 번에:**

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

text_splitter = RecursiveCharacterTextSplitter(chunk_size=200, chunk_overlap=0)

loader = PyPDFLoader("./data/SPRI_AI_Brief_2023년12월호_F.pdf")
split_docs = loader.load_and_split(text_splitter=text_splitter)

print(f"분할된 문서의 수: {len(split_docs)}")
```

**lazy_load() - 대용량 파일에 유용:**

```python
# 제너레이터 방식으로 한 번에 하나씩 로드
for doc in loader.lazy_load():
    print(doc.metadata)
    # 필요한 처리...
```

```python
loader = PyPDFLoader(FILE_PATH)
```

**5. PyPDFLoader with OCR - 스캔된 문서:**


## Chapter 10. Text Splitter - 텍스트 분할

### 왜 텍스트 분할이 필요한가?

RAG에서 문서를 **청크(chunk)** 단위로 나누는 것은 매우 중요하다.

**분할이 필요한 이유:**

1. **검색 정확도** → 질문과 유사한 작은 단위를 찾아야 정확한 답변 가능
2. **LLM 컨텍스트 제한** → 모델마다 입력 토큰 제한이 있음
3. **비용 효율성** → 필요한 부분만 프롬프트에 포함

**청크 크기 트레이드오프:**

| 청크 크기 | 장점        | 단점               |
| :-------- | :---------- | :----------------- |
| 너무 작음 | 정확한 매칭 | 맥락 부족          |
| 너무 큼   | 충분한 맥락 | 불필요한 정보 포함 |

---

### CharacterTextSplitter

가장 간단한 분할기. **단일 구분자**로 텍스트를 나눈다.

```python
from langchain_text_splitters import CharacterTextSplitter

text_splitter = CharacterTextSplitter(
    separator="\n\n",     # 분할 구분자 (기본값: "\n\n")
    chunk_size=210,       # 청크 최대 크기
    chunk_overlap=0,      # 청크 간 중복
    length_function=len,  # 길이 측정 함수
)

# 텍스트 분할
texts = text_splitter.create_documents([file])
print(texts[0])
```

**메타데이터와 함께 분할:**

```python
metadatas = [{"document": 1}, {"document": 2}]

documents = text_splitter.create_documents(
    [file, file],           # 분할할 텍스트들
    metadatas=metadatas,    # 각각의 메타데이터
)
print(documents[0].metadata)  # {'document': 1}
```

---

### RecursiveCharacterTextSplitter

**일반 텍스트에 권장되는 방식**이다. 여러 구분자를 순차적으로 시도한다.

**기본 구분자 순서:** `["\n\n", "\n", " ", ""]`

→ **단락** → **문장** → **단어** 순으로 재귀적으로 분할

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=250,           # 청크 크기
    chunk_overlap=50,         # 중복 허용
    length_function=len,
    is_separator_regex=False,
)

texts = text_splitter.create_documents([file])
print(texts[0])
print("===" * 20)
print(texts[1])  # chunk_overlap으로 인해 앞 청크 끝부분이 포함됨
```

**왜 이게 좋은가?**

- 단락(의미 단위)이 최대한 유지됨
- 청크가 너무 크면 더 작은 단위로 재귀적으로 분할
- 가장 자연스러운 분할점을 찾음

### SemanticChunker - 의미 기반 분할

**의미론적 유사성**에 기반하여 분할한다. 문장 간 임베딩 차이가 클 때 분리한다.

```python
from langchain_experimental.text_splitter import SemanticChunker
from langchain_openai.embeddings import OpenAIEmbeddings

text_splitter = SemanticChunker(OpenAIEmbeddings())

chunks = text_splitter.split_text(file)
print(chunks[0])
```

**작동 원리:**

1. 텍스트를 문장 단위로 분할
2. 3개의 문장씩 그룹화
3. 임베딩 공간에서 유사한 문장들을 병합
4. 유사도가 급격히 떨어지는 지점에서 분리

**Breakpoint 종류:**

| 타입                 | 설명               | 예시                        |
| :------------------- | :----------------- | :-------------------------- |
| `percentile`         | 백분위수 기준 분리 | 상위 30%의 차이에서 분리    |
| `standard_deviation` | 표준편차 기준 분리 | 1.25 표준편차 이상이면 분리 |
| `interquartile`      | 사분위수 범위 기준 | IQR 기반 분리               |

**Percentile 방식:**

```python
text_splitter = SemanticChunker(
    OpenAIEmbeddings(),
    breakpoint_threshold_type="percentile",
    breakpoint_threshold_amount=70,  # 70 백분위수
)
docs = text_splitter.create_documents([file])
```

**Standard Deviation 방식:**

```python
text_splitter = SemanticChunker(
    OpenAIEmbeddings(),
    breakpoint_threshold_type="standard_deviation",
    breakpoint_threshold_amount=1.25,  # 1.25 표준편차
)
```

**Interquartile 방식:**

```python
text_splitter = SemanticChunker(
    OpenAIEmbeddings(),
    breakpoint_threshold_type="interquartile",
    breakpoint_threshold_amount=0.5,
)
```

## 헷갈렸던 부분

### split_text() vs split_documents() vs create_documents()

처음에 이 세 메서드의 차이가 헷갈렸다.

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(chunk_size=100)

# 1. split_text(): 문자열 → 문자열 리스트
text = "긴 텍스트..."
chunks = splitter.split_text(text)  # List[str]

# 2. create_documents(): 문자열 → Document 리스트
docs = splitter.create_documents([text])  # List[Document]
docs = splitter.create_documents([text], metadatas=[{"source": "test"}])

# 3. split_documents(): Document → Document 리스트 (메타데이터 유지!)
from langchain_community.document_loaders import PyPDFLoader
loader = PyPDFLoader("file.pdf")
original_docs = loader.load()

split_docs = splitter.split_documents(original_docs)  # List[Document]
# 원본 메타데이터가 유지됨!
```

| 메서드               | 입력             | 출력             | 메타데이터 |
| :------------------- | :--------------- | :--------------- | :--------- |
| `split_text()`       | `str`            | `List[str]`      | 없음       |
| `create_documents()` | `List[str]`      | `List[Document]` | 직접 지정  |
| `split_documents()`  | `List[Document]` | `List[Document]` | 원본 유지  |

**결론:** Document Loader로 로드한 후에는 `split_documents()`를 쓰면 메타데이터가 자동 유지된다!

### SemanticChunker의 breakpoint 종류

| 타입                 | 언제 쓰나?              | threshold_amount 예시   |
| :------------------- | :---------------------- | :---------------------- |
| `percentile`         | 일반적인 경우           | 70~90 (백분위수)        |
| `standard_deviation` | 명확한 구분이 필요할 때 | 1.0~1.5 (표준편차 배수) |
| `interquartile`      | 이상치에 강건해야 할 때 | 0.5~1.0                 |

**내 생각:** 기본값인 `percentile`로 시작해서 결과를 보고 조정하는 게 좋을 것 같다.

## 궁금해서 더 찾아본 내용

### 1. 한국어 텍스트 분할은 어떻게?

> "한국어는 띄어쓰기가 불규칙한데 어떻게 분할하나?"

**KonlpyTextSplitter 사용:**

```python
from langchain_text_splitters import KonlpyTextSplitter

text_splitter = KonlpyTextSplitter(chunk_size=200, chunk_overlap=50)
texts = text_splitter.split_text(korean_text)
```

KoNLPy의 `Kkma` 분석기를 사용하여:

- 문장을 단어로, 단어를 형태소로 분해
- 각 토큰에 대한 품사 식별
- 긴 텍스트를 개별 문장으로 분할

**주의:** `Kkma`는 정밀하지만 처리 속도가 느릴 수 있다.

### 2. load_and_split()을 쓰면 편하지 않나?

> "loader.load_and_split()이 있는데 왜 따로 분할하나?"

**load_and_split() 장점:**

- 코드가 간결함
- 한 번에 처리

**따로 하는 게 나은 경우:**

1. **분할 전에 전처리가 필요할 때**

   ```python
   docs = loader.load()
   # 불필요한 페이지 제거, 텍스트 정제 등
   cleaned_docs = [preprocess(doc) for doc in docs]
   split_docs = splitter.split_documents(cleaned_docs)
   ```

2. **여러 분할기를 실험할 때**

   ```python
   docs = loader.load()  # 한 번만 로드

   # 여러 설정으로 실험
   split1 = splitter1.split_documents(docs)
   split2 = splitter2.split_documents(docs)
   ```

3. **로딩과 분할 사이에 로직이 필요할 때**

**결론:** 간단한 경우 `load_and_split()`, 복잡한 파이프라인은 분리하는 게 좋다.

## 이번 주 핵심 정리

1. **Document = page_content + metadata** → 모든 문서의 기본 단위
2. **PDF 로더는 상황에 맞게 선택** → AutoRAG 실험 결과 참고 (PDFMiner, PDFPlumber 추천)
3. **RecursiveCharacterTextSplitter가 기본** → 단락 → 문장 → 단어 순으로 자연스럽게 분할
4. **chunk_overlap으로 맥락 유지** → chunk_size의 10~20% 권장
5. **SemanticChunker는 실험적** → 의미 기반 분할이 필요하면 시도
6. **split_documents()로 메타데이터 유지** → Document 객체를 분할할 때 사용
7. **코드는 from_language() 사용** → 언어별 적절한 구분자 자동 적용
