### **유사도 계산**

```python
import numpy as np

# 코사인 유사도
def cosine_similarity(vec1, vec2):
    dot_product = np.dot(vec1, vec2)
    norm1 = np.linalg.norm(vec1)
    norm2 = np.linalg.norm(vec2)
    return dot_product / (norm1 * norm2)

query_vector = [0.1, 0.8, 0.3, ...]      # "OOP가 뭐야?"
doc1_vector = [0.2, 0.7, 0.4, ...]       # "객체지향 프로그래밍..."
doc2_vector = [0.9, 0.1, 0.2, ...]       # "자동차 엔진..."

similarity1 = cosine_similarity(query_vector, doc1_vector)  # 0.95 (높음)
similarity2 = cosine_similarity(query_vector, doc2_vector)  # 0.12 (낮음)

# 결과: doc1이 더 관련성 높음
```

## 벡터 스토어 종류 비교

### Chroma

```python
vectorstore = Chroma(
    collection_name="my_collection",
    embedding_function=embeddings,
    persist_directory="./chroma_db"
)
```

**장점**: 설치 쉬움, 로컬 실행, 가벼움, 무료

**단점**: 대용량 처리 약함, 분산 처리 X

**용도**: 개발/테스트, 중소규모 프로젝트

### FAISS (Meta)

```python
vectorstore = FAISS.from_documents(
    documents,
    embeddings
)
```

**장점**: 매우 빠름, 대용량 처리, 고성능, 무료

**단점**: 메모리 기반, 메타데이터 필터링 약함

**용도**: 성능 중요, 단순 유사도 검색

### Pinecone (클라우드)

```python
pinecone.init(api_key="...")
vectorstore = Pinecone.from_documents(
    documents,
    embeddings,
    index_name="my-index"
)
```

**장점**: 완전 관리형, 확장성, 메타데이터 필터링 강력

**단점**: 유료, 벤더 종속

**용도**: 프로덕션, 대규모 서비스

### Weaviate

```python
vectorstore = Weaviate.from_documents(
```

**장점**: 오픈소스, 기능 풍부, GraphQL

**용도**: 복잡한 쿼리, 커스터마이징

### 어떤 메타데이터가 필요할까?

1. 기본 메타데이터 (모든 프로젝트)
    
    ```python
    base_metadata = {
        # 식별
        "id": "doc_001",
        "source": "textbook.pdf",
    
        # 시간
        "created_at": "2024-01-15T10:30:00Z",
        "updated_at": "2024-01-20T15:45:00Z",
    
        # 구조
        "page": 42,
        "chapter": 3,
        "section": "3.2"
    }
    ```
    
2. 도메인 특화 메타데이터
    
    ```python
    # 책이라면?
    study_metadata = {
        # 분류 - 과목 > 주제 > 소주제
        "subject": "컴퓨터공학",
        "topic": "객체지향 프로그래밍",
        "subtopic": "캡슐화",
    
        # 난이도
        "difficulty": "중급",
        "prerequisite": ["변수", "함수", "클래스"],
    
        # 학습 목표
        "learning_objectives": [
            "캡슐화 개념 이해",
            "접근 제어자 활용"
        ],
    
        # 콘텐츠 타입
        "content_type": "explanation",  # explanation/example/exercise/summary
    
        # 언어
        "language": "ko",
    
        # 저자/출처
        "author": "홍길동",
        "institution": "서울대학교",
    
        # 품질
        "verified": True,  # 검증된 자료
        "popularity": 0.85,  # 인기도 (0-1)
    
        # 관련성
        "related_topics": ["상속", "다형성"],
        "keywords": ["캡슐화", "private", "public", "getter", "setter"]
    }
    ```
    
    **메타데이터는**
    
    1. 검색에 사용할 필드만 (필터링)
    2. 계층 구조 : `분류 - 과목 > 주제 > 소주제`
    3. 정규화된 값
        
        ❌ : `difficulty = "쉬움" vs "쉬운" vs "easy" vs "초급"`
        
        ⭕ : enum/숫자  `difficulty = "beginner" # beginner/intermediate/advanced`
        
    4. 타입 일관성

### **MMR (Maximum Marginal Relevance)**

```python
query = "객체지향 프로그래밍"
```

```python
results = vectorstore.similarity_search(query, k=5)
# 결과:
# 1. "OOP는 프로그래밍 패러다임..."
# 2. "객체지향은 소프트웨어 설계..."
# 3. "OOP의 핵심은..."
# 4. "객체지향 프로그래밍이란..."
# 5. "OOP 개념 정리..."
```

질문에 대해 다양성이 필요하다면?

```python
results = vectorstore.max_marginal_relevance_search(
    query,
    k=5,
    fetch_k=20,  # 후보 20개
    lambda_mult=0.5  # 0~1, 0.5가 균형
)

# 결과 (개선):
# 1. "OOP는 프로그래밍 패러다임..."
# 2. "캡슐화의 중요성..."  (구체적 주제)
# 3. "Java에서 OOP 구현..."  (실습)
# 4. "함수형 vs 객체지향..."  (비교)
# 5. "디자인 패턴..."  (응용)
```

**lambda_mult**

- 1.0: 유사도만 고려 (다양성 X)
- 0.5: 유사도 + 다양성 균형
- 0.0: 다양성만 고려 (관련성 X)

## **재순위화(Re-ranking)**

1. 벡터 검색으로 후보 20개
2. 재순위 모델로 정확도 재평가
3. 상위 5개만 반환

**장점**

- 정확도 향상
- 벡터 검색의 한계 보완

**단점**

- 추가 비용 (Cohere API)
- 처리 시간 증가

### 재순위가 필요한 경우

1. 벡터 검색은 ‘의미적 유사도’만 보기 때문에 의미는 덜 유사하지만 정답일 경우 문제가 됨
2. 상황
    1. 정확한 답변이 중요한 경우
    2. 복잡한 질문
    3. 순위가 중요한 경우
