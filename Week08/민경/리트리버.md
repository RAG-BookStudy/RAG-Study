## 리트리버 = 문서 검색 추상화 계층

### 왜 필요한가?

1. 통일된 인터페이스: 다양한 검색 방식을 같은 방법으로 사용
2. 조합 가능: 여러 리트리버를 결합
3. 체인 통합: LangChain의 다른 컴포넌트와 쉽게 연결

### **리트리버 종류**

- VectorStoreRetriever - 가장 기본
- BM25Retriever - 키워드 검색
- EnsembleRetriever - (벡터 + 키워드
- ContextualCompressionRetriever - 재순위/압축
- MultiQueryRetriever - 쿼리 확장

---

### **MultiQueryRetriever**

1. 원본 쿼리 → LLM이 유사 쿼리 여러 개 생성
2. 각 쿼리로 검색
3. 결과 합침 + 중복 제거

```python
query = "OOP란?"

# 생성된 쿼리들
# - "객체지향 프로그래밍이란 무엇인가?"
# - "OOP의 정의와 특징"
# - "객체지향의 개념 설명"
# - "Object-Oriented Programming 설명"
```

**장점**

- 쿼리가 모호할 때 유용
- 다양한 관점에서 검색
- 놓칠 수 있는 문서 발견

**단점**

- LLM 호출 비용
- 느림
- 중복 결과 많을 수 있음

---

### **ContextualCompressionRetriever**

검색된 문서가 너무 길고 관련 없는 내용 포함할 때

1. LLM으로 관련 부분만 추출
    1. 원본: "Spring Boot는... (3000자)"
    2. 압축 후: "Spring Boot의 JPA 설정은... (500자)"
    
    → 질문에 관련된 부분만 추출
    
    ```python
    llm = ChatOpenAI(temperature=0)
    compressor = LLMChainExtractor.from_llm(llm)
    
    compression_retriever = ContextualCompressionRetriever(
        base_compressor=compressor,
        base_retriever=base_retriever
    )
    ```
    
2. Embeddings Filter (유사도 재계산)
    1. 후보 문서 20개 검색
    2. 각 문서와 쿼리의 유사도 재계산
    3. 0.76 이상만 통과
    4. 상위 5개 반환
    
    ```python
    embeddings_filter = EmbeddingsFilter(
        embeddings=embeddings,
        similarity_threshold=0.76
    )
    
    compression_retriever = ContextualCompressionRetriever(
        base_compressor=embeddings_filter,
        base_retriever=base_retriever
    )
    ```

### **ParentDocumentRetriever**

- 작은 청크: 검색 정확 + 문맥 부족
- 큰 청크: 문맥 충분 + 검색 부정확

⇒ 작은 청크로 검색 → 큰 문서 반환

1. 부모 문서 (2000자) → 자식 청크 (400자씩 5개)
2. 자식 청크를 벡터 DB에 저장
3. 검색 시: 자식 청크로 검색
4. 반환 시: 부모 문서 전체 반환

## 벡터 스토어 vs리트리버

### **벡터 스토어 = 저장소 + 검색 엔진**

- 데이터 관리 (CRUD)
- 인덱스 관리
- 검색 알고리즘 구현
- 벡터 스토어마다 다른 API

### **리트리버** = 통일된 검색 인터페이스

- 검색만 담당 (저장 X)
- 표준 인터페이스
- 어떤 리트리버든 같은 방식으로 사용

벡터 스토어 = 구체적 구현

리트리버 = 추상 인터페이스
