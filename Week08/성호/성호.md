## Chapter 12. VectorStore - 벡터스토어

### 벡터스토어란?

벡터스토어는 임베딩된 벡터를 저장하고, 유사도 검색을 수행하는 데이터베이스다. RAG 파이프라인에서 문서를 저장하고 검색하는 핵심 컴포넌트 역할을 한다.

**벡터스토어의 역할:**

1. 임베딩된 문서 벡터를 저장
2. 쿼리와 유사한 문서를 빠르게 검색
3. 메타데이터 기반 필터링 지원

---

### Chroma

Chroma는 개발자의 생산성에 초점을 맞춘 AI 네이티브 오픈 소스 벡터 데이터베이스다. Apache 2.0 라이선스로 제공된다.

**VectorStore 생성 (from_documents):**

```python
from langchain_community.document_loaders import TextLoader
from langchain_openai.embeddings import OpenAIEmbeddings
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_chroma import Chroma

# 텍스트 분할
text_splitter = RecursiveCharacterTextSplitter(chunk_size=600, chunk_overlap=0)

loader = TextLoader("data/nlp-keywords.txt")
split_doc = loader.load_and_split(text_splitter)

# DB 생성
db = Chroma.from_documents(
    documents=split_doc, embedding=OpenAIEmbeddings(), collection_name="my_db"
)
```

**주요 매개변수:**

| 매개변수 | 설명 | 기본값 |
| :--- | :--- | :--- |
| `documents` | 벡터 저장소에 추가할 문서 리스트 | - |
| `embedding` | 임베딩 함수 | None |
| `collection_name` | 생성할 컬렉션 이름 | - |
| `persist_directory` | 컬렉션을 저장할 디렉토리 | None |

**디스크에 저장 (persist_directory):**

```python
DB_PATH = "./chroma_db"

# 문서를 디스크에 저장
persist_db = Chroma.from_documents(
    split_doc, OpenAIEmbeddings(), persist_directory=DB_PATH, collection_name="my_db"
)

# 디스크에서 불러오기
persist_db = Chroma(
    persist_directory=DB_PATH,
    embedding_function=OpenAIEmbeddings(),
    collection_name="my_db",
)
```

> `persist_directory`가 지정되지 않으면 데이터는 메모리에 임시로 저장된다.

**from_texts - 텍스트 리스트로 생성:**

```python
db2 = Chroma.from_texts(
    ["안녕하세요. 정말 반갑습니다.", "제 이름은 테디입니다."],
    embedding=OpenAIEmbeddings(),
)
```

### Chroma - 유사도 검색

**similarity_search:**

```python
# 기본 검색 (k=4)
db.similarity_search("TF IDF 에 대하여 알려줘")

# k 값 지정
db.similarity_search("TF IDF 에 대하여 알려줘", k=2)

# metadata 필터링
db.similarity_search(
    "TF IDF 에 대하여 알려줘", filter={"source": "data/nlp-keywords.txt"}, k=2
)
```

**주요 매개변수:**

| 매개변수 | 설명 | 기본값 |
| :--- | :--- | :--- |
| `query` | 검색할 쿼리 텍스트 | - |
| `k` | 반환할 결과의 수 | 4 |
| `filter` | 메타데이터로 필터링 | None |

### FAISS

Facebook AI Similarity Search (FAISS)는 밀집 벡터의 효율적인 유사도 검색과 클러스터링을 위한 라이브러리다. RAM에 맞지 않을 수도 있는 벡터 집합도 검색할 수 있다.

**FAISS 벡터 저장소 초기화:**

```python
import faiss
from langchain_community.vectorstores import FAISS
from langchain_community.docstore.in_memory import InMemoryDocstore
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
dimension_size = len(embeddings.embed_query("hello world"))

# 빈 FAISS 벡터 저장소 생성
db = FAISS(
    embedding_function=embeddings,
    index=faiss.IndexFlatL2(dimension_size),
    docstore=InMemoryDocstore(),
    index_to_docstore_id={},
)
```

**from_documents / from_texts:**

```python
# 문서로부터 생성
db = FAISS.from_documents(documents=split_doc1, embedding=OpenAIEmbeddings())

# 텍스트로부터 생성
db2 = FAISS.from_texts(
    ["안녕하세요. 정말 반갑습니다.", "제 이름은 테디입니다."],
    embedding=OpenAIEmbeddings(),
    metadatas=[{"source": "텍스트문서"}, {"source": "텍스트문서"}],
    ids=["doc1", "doc2"],
)
```

### FAISS - 저장 및 로드

Chroma와 달리 FAISS는 별도의 `save_local` / `load_local` 메서드를 사용한다.

**로컬 저장:**

```python
db.save_local(folder_path="faiss_db", index_name="faiss_index")
```

**로컬 로드:**

```python
loaded_db = FAISS.load_local(
    folder_path="faiss_db",
    index_name="faiss_index",
    embeddings=embeddings,
    allow_dangerous_deserialization=True,  # pickle 역직렬화 허용
)
```

> `allow_dangerous_deserialization=True`를 설정해야 pickle 파일을 로드할 수 있다. pickle 사용으로 인한 보안 위험을 고려해야 한다.

**FAISS 객체 병합 (merge_from):**

```python
db2 = FAISS.from_documents(documents=split_doc2, embedding=OpenAIEmbeddings())

# db에 db2를 병합
db.merge_from(db2)
```

### Pinecone

Pinecone은 완전 관리형 클라우드 벡터 데이터베이스다. 대규모 프로덕션 환경에 적합하다.

**Chroma/FAISS vs Pinecone 비교:**

| 항목 | Chroma/FAISS | Pinecone |
| :--- | :--- | :--- |
| 호스팅 | 로컬/셀프 호스팅 | 클라우드 관리형 |
| 비용 | 무료 (오픈소스) | 유료 (Free tier 있음) |
| 확장성 | 제한적 | 뛰어남 |
| 커스터마이징 | 자유도 높음 | 제한적 |
| 데이터 위치 | 로컬 제어 가능 | 클라우드 저장 |

**인덱스 생성:**

```python
import os
from langchain_teddynote.community.pinecone import create_index

pc_index = create_index(
    api_key=os.environ["PINECONE_API_KEY"],
    index_name="teddynote-db-index",
    dimension=4096,  # Embedding 차원과 맞춤 (OpenAI: 1536, Upstage: 4096)
    metric="dotproduct",  # dotproduct, euclidean, cosine
)
```

**Sparse Encoder 생성 (한국어 하이브리드 검색):**

```python
from langchain_teddynote.community.pinecone import (
    create_sparse_encoder,
    fit_sparse_encoder,
)
from langchain_teddynote.korean import stopwords

# Kiwi 형태소 분석기 + 한글 불용어 사전
sparse_encoder = create_sparse_encoder(stopwords(), mode="kiwi")

# Corpus 학습 및 저장
saved_path = fit_sparse_encoder(
    sparse_encoder=sparse_encoder, contents=contents, save_path="./sparse_encoder.pkl"
)
```

**문서 Upsert:**

```python
from langchain_teddynote.community.pinecone import upsert_documents
from langchain_upstage import UpstageEmbeddings

upsert_documents(
    index=pc_index,
    namespace="teddynote-namespace-01",
    contents=contents,
    metadatas=metadatas,
    sparse_encoder=sparse_encoder,
    embedder=UpstageEmbeddings(model="solar-embedding-1-large-passage"),
    batch_size=32,
)
```

**대용량 분산 처리 Upsert:**

```python
from langchain_teddynote.community.pinecone import upsert_documents_parallel

upsert_documents_parallel(
    index=pc_index,
    namespace="teddynote-namespace-02",
    contents=contents,
    metadatas=metadatas,
    sparse_encoder=sparse_encoder,
    embedder=UpstageEmbeddings(model="solar-embedding-1-large-passage"),
    batch_size=64,
    max_workers=30,
)
```

### Pinecone - HybridSearch Retriever

Pinecone은 Dense + Sparse 벡터를 결합한 하이브리드 검색을 지원한다.

**검색기 초기화:**

```python
from langchain_teddynote.community.pinecone import (
    init_pinecone_index,
    PineconeKiwiHybridRetriever,
)
from langchain_upstage import UpstageEmbeddings

pinecone_params = init_pinecone_index(
    index_name="teddynote-db-index",
    namespace="teddynote-namespace-02",
    api_key=os.environ["PINECONE_API_KEY"],
    sparse_encoder_path="./sparse_encoder.pkl",
    stopwords=stopwords(),
    tokenizer="kiwi",
    embeddings=UpstageEmbeddings(model="solar-embedding-1-large-query"),
    top_k=5,
    alpha=0.5,  # 0.75: Dense 75%, Sparse 25%
)

pinecone_retriever = PineconeKiwiHybridRetriever(**pinecone_params)
```

**alpha 파라미터:**

| alpha 값 | Dense 비중 | Sparse 비중 | 설명 |
| :---: | :---: | :---: | :--- |
| 0.0 | 0% | 100% | 키워드 매칭만 (BM25 유사) |
| 0.5 | 50% | 50% | 균형 잡힌 검색 (기본값) |
| 1.0 | 100% | 0% | 의미 기반 검색만 |

**동적 search_kwargs:**

```python
# k 조절
results = pinecone_retriever.invoke("검색어", search_kwargs={"k": 1})

# alpha 조절
results = pinecone_retriever.invoke("검색어", search_kwargs={"alpha": 1, "k": 1})

# metadata 필터링
results = pinecone_retriever.invoke(
    "검색어",
    search_kwargs={"filter": {"source": {"$eq": "문서명.pdf"}}, "k": 3},
)

# Reranking 적용
results = pinecone_retriever.invoke(
    "검색어",
    search_kwargs={"rerank": True, "rerank_model": "bge-reranker-v2-m3", "top_n": 3},
)
```

### 벡터스토어를 검색기(Retriever)로 변환

`as_retriever` 메서드는 벡터스토어를 `VectorStoreRetriever`로 변환한다. Chroma, FAISS 모두 동일한 인터페이스를 제공한다.

**검색 유형:**

| search_type | 설명 |
| :--- | :--- |
| `similarity` | 유사도 기반 검색 (기본값) |
| `mmr` | Maximal Marginal Relevance - 다양성 고려 |
| `similarity_score_threshold` | 임계값 이상의 유사도만 반환 |

**사용 예시:**

```python
# 기본 검색 (k=4)
retriever = db.as_retriever()
retriever.invoke("Word2Vec 에 대하여 알려줘")

# MMR 검색 - 다양성 높은 결과
retriever = db.as_retriever(
    search_type="mmr", search_kwargs={"k": 6, "lambda_mult": 0.25, "fetch_k": 10}
)

# 임계값 기반 검색
retriever = db.as_retriever(
    search_type="similarity_score_threshold", search_kwargs={"score_threshold": 0.8}
)

# 메타데이터 필터 적용
retriever = db.as_retriever(
    search_kwargs={"filter": {"source": "data/finance-keywords.txt"}, "k": 2}
)
```

**MMR 주요 파라미터:**

| 파라미터 | 설명 | 기본값 |
| :--- | :--- | :--- |
| `k` | 반환할 문서 수 | 4 |
| `fetch_k` | MMR 알고리즘에 전달할 문서 수 | 20 |
| `lambda_mult` | 다양성 조절 (0: 다양성만, 1: 유사도만) | 0.5 |

## 헷갈렸던 부분

### Chroma vs FAISS - 언제 뭘 쓰나?

처음에 둘 다 로컬에서 사용하는 벡터 DB인데 뭐가 다른지 헷갈렸다.

| 항목 | Chroma | FAISS |
| :--- | :--- | :--- |
| 저장 방식 | `persist_directory`로 자동 저장 | `save_local()` / `load_local()` 수동 관리 |
| 컬렉션 관리 | `collection_name`으로 namespace 분리 | `merge_from()`으로 DB 병합 |
| 문서 삭제 | `delete(ids=[...])` 지원 | `delete(ids=[...])` 지원 |
| 초기화 | `reset_collection()` | 해당 없음 (재생성 필요) |
| 멀티모달 | `add_images()` 지원 | 지원 안 함 |
| 역직렬화 | 안전 | pickle 사용 (보안 주의) |

**결론:** 간단한 프로토타입이나 멀티모달이 필요하면 Chroma, 대규모 벡터 검색 성능이 중요하면 FAISS가 적합하다.

---

### from_documents vs from_texts

두 메서드 모두 벡터스토어를 생성하지만 입력 형태가 다르다.

| 메서드 | 입력 | 메타데이터 |
| :--- | :--- | :--- |
| `from_documents()` | `List[Document]` | Document 내 metadata 자동 사용 |
| `from_texts()` | `List[str]` | `metadatas` 파라미터로 직접 전달 |

```python
# from_documents - Document Loader 결과를 바로 사용
db = FAISS.from_documents(documents=split_docs, embedding=OpenAIEmbeddings())

# from_texts - 텍스트와 메타데이터를 직접 지정
db = FAISS.from_texts(
    ["텍스트1", "텍스트2"],
    embedding=OpenAIEmbeddings(),
    metadatas=[{"source": "a.txt"}, {"source": "b.txt"}],
)
```

**결론:** Document Loader로 로드한 문서는 `from_documents()`, 직접 텍스트를 넣을 때는 `from_texts()`를 사용하면 된다.

---

### similarity_search vs as_retriever 차이

| 방식 | 반환값 | 체인 연결 |
| :--- | :--- | :--- |
| `db.similarity_search()` | `List[Document]` | 불가 (직접 호출) |
| `db.as_retriever().invoke()` | `List[Document]` | LCEL 체인에 연결 가능 |

```python
# 직접 검색
docs = db.similarity_search("쿼리", k=3)

# Retriever로 변환 후 체인에 연결
retriever = db.as_retriever(search_kwargs={"k": 3})
chain = retriever | prompt | llm  # LCEL 체인 구성 가능
```

**결론:** RAG 파이프라인을 구축할 때는 `as_retriever()`로 변환해서 체인에 연결하는 것이 표준 패턴이다.

## 궁금해서 더 찾아본 내용

### 1. Pinecone의 HybridSearch가 왜 좋은가?

> "Dense 검색만으로 충분하지 않나?"

Dense 검색(벡터 유사도)만으로는 **키워드 정확 매칭**이 어렵다.

예를 들어 "앤스로픽"이라는 고유명사를 검색할 때:
- **Dense (alpha=1)**: 의미적으로 유사한 문서를 찾지만 정확한 키워드 매칭이 약함
- **Sparse (alpha=0)**: BM25 기반으로 "앤스로픽" 키워드가 포함된 문서를 정확히 찾음
- **Hybrid (alpha=0.5)**: 둘을 결합하여 균형 잡힌 검색 결과 제공

**결론:** 한국어 검색에서는 특히 고유명사, 전문 용어가 중요하므로 HybridSearch가 효과적이다.

---

### 2. metric 선택 기준 (dotproduct vs cosine vs euclidean)

> "Pinecone에서 metric을 dotproduct로 설정하는 이유가 뭔가?"

| metric | 설명 | 사용 조건 |
| :--- | :--- | :--- |
| `cosine` | 코사인 유사도 | 정규화되지 않은 벡터 |
| `dotproduct` | 벡터 내적 | 정규화된 벡터, HybridSearch 필수 |
| `euclidean` | 유클리드 거리 | 거리 기반 비교 |

**HybridSearch를 사용하려면 `dotproduct`를 반드시 선택해야 한다.** Dense와 Sparse 벡터의 점수를 합산하는 방식이기 때문이다.

---

### 3. FAISS의 IndexFlatL2 vs 다른 인덱스

> "IndexFlatL2만 사용해도 되나?"

| 인덱스 | 설명 | 속도 | 정확도 |
| :--- | :--- | :--- | :--- |
| `IndexFlatL2` | 전수 조사 (Brute-force) | 느림 | 100% |
| `IndexIVFFlat` | 클러스터 기반 근사 검색 | 빠름 | 높음 |
| `IndexHNSW` | 그래프 기반 근사 검색 | 매우 빠름 | 높음 |

소규모 데이터(수만 건 이하)에서는 `IndexFlatL2`로 충분하지만, 대규모 데이터에서는 근사 검색 인덱스를 사용하는 것이 좋다.

## 이번 주 핵심 정리

1. **Chroma는 간편한 로컬 벡터 DB** → `persist_directory`로 디스크 저장, `collection_name`으로 namespace 관리
2. **FAISS는 고성능 벡터 검색** → Facebook AI 제작, `save_local`/`load_local`로 저장/로드, `merge_from`으로 DB 병합
3. **Pinecone은 클라우드 관리형** → HybridSearch 지원, 대규모 프로덕션에 적합
4. **as_retriever()로 검색기 변환** → LCEL 체인에 연결 가능, MMR/임계값/필터 등 다양한 검색 옵션
5. **HybridSearch = Dense + Sparse** → alpha로 가중치 조절, 한국어 고유명사 검색에 효과적
6. **멀티모달 검색은 Chroma** → OpenCLIP 임베딩으로 이미지 저장/검색 가능
7. **벡터 DB 선택은 상황에 따라** → 프로토타입은 Chroma, 성능은 FAISS, 프로덕션은 Pinecone
